1. How to learn

Do not memorize syntax. Understand what the code does and practise it.

  • Type: manually type every example.
  • Predict: say the expected output before running.
  • Change: modify a value and predict again.
  • Connect: use users, test cases, URLs, browsers and API data.
  • Explain: explain your own code before moving forward.
Rule: use const by default, let when reassignment is required, and avoid var in modern code.

3. Variables — const and let

JavaScript variables do not require a declared type.

const name = "Sibi";
let retryCount = 0;
retryCount = retryCount + 1;

console.log(name);
console.log(retryCount);

const prevents reassignment of the binding. let allows reassignment.

undefined and null

let result;
console.log(result); // undefined

const selectedUser = null;
console.log(selectedUser); // null

const does not freeze objects

const user = { name: "Sibi", role: "Tester" };
user.role = "Automation Engineer"; // allowed
// user = {}; // not allowed
Added explanation: const protects the variable binding, not every property inside an object or array.

4. Data types

Core beginner types: string, number, boolean, undefined, null, object and array.

const browser = "chromium"; // string
const timeout = 5000;       // number
const active = true;        // boolean
let value;                  // undefined
const missing = null;       // null
const browsers = ["chromium", "firefox"]; // array
const user = { name: "Sibi" };             // object

typeof

console.log(typeof "Hello");   // string
console.log(typeof 25);        // number
console.log(typeof true);      // boolean
console.log(typeof undefined); // undefined
Completeness note: Symbol and BigInt exist, but they are not needed for this beginner automation path.

5. Operators, equality and truthy/falsy

const a = 10;
const b = 3;

console.log(a + b);
console.log(a - b);
console.log(a * b);
console.log(a / b);
console.log(a % b);

console.log(5 === 5);   // true
console.log(5 === "5"); // false
console.log(5 !== "5"); // true

Prefer === and !== because they compare value and type.

Logical operators

const age = 25;
const hasId = true;

console.log(age >= 18 && hasId);
console.log(age < 18 || hasId);
console.log(!hasId);

Truthy/falsy

Common falsy values: false, 0, "", null, undefined, NaN. Most other values are truthy, including empty arrays and objects.

const errorMessage = "";

if (errorMessage) {
  console.log("Error exists");
} else {
  console.log("No error");
}

6. Conditions

const marks = 75;

if (marks >= 50) {
  console.log("Pass");
} else {
  console.log("Fail");
}
const status = "PASS";

switch (status) {
  case "PASS":
    console.log("Test passed");
    break;
  case "FAIL":
    console.log("Test failed");
    break;
  default:
    console.log("Unknown status");
}
Automation connection: conditions are used for status codes, login state, expected text, feature flags and test data.

7. Loops

for (let i = 1; i <= 5; i++) {
  console.log(i);
}

let count = 1;
while (count <= 5) {
  console.log(count);
  count++;
}

const browsers = ["chromium", "firefox", "webkit"];
for (const browser of browsers) {
  console.log(browser);
}

Use for...of when you want array values directly. Learn break and continue for controlling loops.

8. Functions and arrow functions

function add(a, b) {
  return a + b;
}

const result = add(10, 20);
console.log(result); // 30

const multiply = (a, b) => a * b;
console.log(multiply(4, 5));

Parameters are names in the function definition. Arguments are the actual values passed when calling it.

Default parameter

function greet(name = "Guest") {
  return `Hello ${name}`;
}

Function calling another function

function double(n) {
  return n * 2;
}
function processNumber(n) {
  return double(n) + 10;
}
Automation connection: helpers such as login(), createUser() and getTestData() are reusable functions.

9. Template literals

Use backticks and ${...} for dynamic strings.

const username = "Sibi";
const testName = `Login test for ${username}`;

const userId = 101;
const url = `https://example.com/users/${userId}`;

console.log(testName);
console.log(url);

Useful for dynamic URLs, messages, test names and logs.

10. Objects

const user = {
  name: "Sibi",
  role: "Automation Tester",
  active: true
};

console.log(user.name);
console.log(user["role"]);

const fieldName = "role";
console.log(user[fieldName]);

Dot access is normal. Bracket access is useful when the property name is dynamic.

Nested object

const employee = {
  name: "Sibi",
  address: {
    city: "Chennai",
    country: "India"
  }
};

console.log(employee.address.city);

Object method

const user = {
  name: "Sibi",
  greet() {
    return `Hello ${this.name}`;
  }
};

console.log(user.greet());

11. Arrays and array methods

const browsers = ["chromium", "firefox", "webkit"];

console.log(browsers[0]);
console.log(browsers.length);

browsers.push("mobile");
browsers.pop();

console.log(browsers.includes("firefox"));

  { name: "Asha", active: true },
  { name: "Ravi", active: false },
  { name: "John", active: true }

Remember: map → new transformed array; filter → smaller array; find → one item; forEach → execute code; reduce → one accumulated result.

12. Destructuring and spread

const user = { name: "Sibi", role: "Tester" };
const { name, role } = user;

const colors = ["Red", "Blue", "Green"];
const [first, second] = colors;

const firstList = [1, 2, 3];
const secondList = [4, 5, 6];
const combined = [...firstList, ...secondList];

const updatedUser = { ...user, role: "Automation Engineer" };

Destructuring is common with API responses and function results. Spread is useful for creating updated arrays/objects without manually copying each property.

13. Modules

Modules split reusable code across files.

// math.js
export function add(a, b) {
  return a + b;
}

// app.js
import { add } from "./math.js";

console.log(add(10, 20));
Automation connection: Playwright projects commonly separate tests, page objects, test data, utilities and configuration. Modules support that structure.

14. Error handling

try {
  const value = JSON.parse("invalid");
  console.log(value);
} catch (error) {
  console.log("Something went wrong");
}
function divide(a, b) {
  if (b === 0) {
    throw new Error("Cannot divide by zero");
  }
  return a / b;
}

try {
  console.log(divide(10, 0));
} catch (error) {
  console.log(error.message);
}

Use errors to make failures controlled, meaningful and easier to debug.

15. Promises and async/await

Network calls, timers, file access and browser actions can take time. Promises represent future results.

const promise = new Promise((resolve) => {
  setTimeout(() => resolve("Finished"), 1000);
});

promise.then(result => console.log(result));
async function getMessage() {
  return "Hello";
}

async function run() {
  try {
    const message = await getMessage();
    console.log(message);
  } catch (error) {
    console.log("Failed:", error);
  }
}

run();
Playwright connection: browser actions are asynchronous, so you will frequently see await page.goto(...), await page.locator(...).click() and await expect(...).

16. Browser/DOM basics — added for completeness

The supplied PDFs do not cover DOM basics. Because your goal includes front-end development and Playwright, a short introduction is useful.

const button = document.querySelector("#loginButton");

button.addEventListener("click", () => {
  console.log("Login clicked");
});
const title = document.querySelector("h1");

console.log(title.textContent);
title.textContent = "Login Page";

You do not need deep DOM knowledge before Playwright, but you should understand elements, selectors, text and events.

17. Integration exercise

const testCases = [
  { name: "Login test", username: "admin", status: "PASS" },
  { name: "Invalid login", username: "wrong-user", status: "FAIL" }
];

const passedCases = testCases.filter(
  testCase => testCase.status === "PASS"
);

for (const testCase of passedCases) {
  const { name, username } = testCase;
  console.log(`Running: ${name}`);
  console.log(`Username: ${username}`);
}
  • const stores the array.
  • Objects represent records.
  • filter selects PASS cases.
  • for...of iterates over them.
  • Destructuring extracts properties.
  • Template literals build readable logs.
  • Arrow functions are used inside filter.

18. Mini project — data-driven login model

const loginUsers = [
  {
    username: "validUser",
    password: "correctPassword",
    expected: "success"
  },
  {
    username: "invalidUser",
    password: "wrongPassword",
    expected: "error"
  }
];

const getUserByExpectedResult = (expected) =>
  loginUsers.find(user => user.expected === expected);

Your tasks

  1. Add a third user with expected "error".
  2. Use filter to get all error users.
  3. Use map to extract usernames.
  4. Use for...of to print them.
  5. Use template literals for readable output.
  6. Use destructuring.
  7. Add validation with throw and try/catch.
  8. Move the helper into another module.
  9. Add an async function that simulates loading test data.

19. Seven-day hands-on plan

Target 2–3 hours each day: 45–60 minutes learning, 60–90 minutes coding and 15–30 minutes revision.

Day 1 — Variables + Data Types
Create 15 variables. Practise string, number, boolean, null, undefined, arrays, objects and typeof. Build a personal profile program.
Day 2 — Operators + Conditions
Practise arithmetic, comparison, strict equality, logical operators and truthy/falsy. Build a marks calculator and age check.
Day 3 — Loops + Template Literals
Practise for, while, for...of, break and continue. Print 1–50, even numbers, a multiplication table, a sum and array values. Build dynamic messages.
Day 4 — Functions
Write at least 12 functions. Practise parameters, returns, defaults, expressions and arrow functions. Build a calculator with validation.
Day 5 — Arrays + Objects
Practise push, pop, includes, forEach, map, filter, find and reduce. Create arrays of test/user objects.
Day 6 — Destructuring + Spread + Modules + Errors
Split the project into files and add validation, try/catch and throw.
Day 7 — Promises + async/await + Revision
Practise asynchronous code, complete the mini project and explain every major line without the guide.
Added: Template literals and DOM/browser basics are included because they were not fully covered in the supplied material and are directly useful for front-end/Playwright work.

20. Common beginner mistakes

  • Using var everywhere → prefer const/let.
  • Using == → normally prefer ===.
  • Thinking const makes objects immutable → it does not.
  • Overusing indexes → prefer for...of or array methods.
  • Writing huge functions → split reusable behaviour.
  • Ignoring return values → know what each array method returns.
  • Confusing [] arrays with {} objects.
  • Copy/pasting without prediction.
  • Trying to learn everything at once.
  • Rushing async/await.
